## 一、先说结论：三个真正的变化

### 传播点 1｜从「翻库找」到「描述出来」

做过游戏的人都知道这个场景：

> 需要一个「轻盈的 UI 弹出音」。
>
> 打开音效库，搜 `pop`，出来 40 个结果，一个个点开听。听完发现都不太对 —— 要么太电子，要么尾巴太长。
>
> 于是去调音，或者……凑合用。

**翻库的本质是"在别人做好的有限集合里挑一个最不差的"。**

而描述的本质是**直接说出你要什么**：

> 气泡弹出般的轻快音效，短促俏皮

一秒生成。不满意就改两个词再生成一次 —— **改词的代价远小于翻库的代价**。

### 传播点 2｜"可无缝循环"这个开关，游戏人才懂它值多少

这是我最想说的一个点，因为它**只有做过游戏的人才会立刻反应它的价值**。

游戏里的**环境音**（雨声、风声、海浪、人群）是**长时间播放**的。如果你拿一段 10 秒的雨声直接循环，每次循环接缝处会有一次**明显的"咔嗒"**或音量断层 —— 玩家在安静场景里戴耳机一定能听出来。

以前的解法很麻烦：要么手工在音频软件里找零交叉点、做交叉淡化；要么把素材拉得特别长来掩盖接缝。

现在生成时勾一个 **「可无缝循环」**，产出的素材**首尾天然衔接**，直接丢进引擎循环播放就行。

> **做环境音的，这一个开关就能省掉一个下午。**

### 传播点 3｜它是资产管线的**上游**，不是终点

生成的音效直接落进工程的 `Cache/Sfx`，能被挂上轨道、能被合成、能作为资产导出。

不是"下载一个 wav 到你的下载文件夹"，而是**进到你的工程里**。

## 二、三步上手：一句话出一个音效

### ① 加「音效」节点

画布右键 → **「声音」** 分组 → 音效。

### ② 写描述，点运行

指令框里写的**就是你要的声音**：

```
游戏UI按钮点击，清脆短促，干净无混响
```

三个 Inspector 开关按需调：

| 开关             | 说明                                                                  |
| ---------------- | --------------------------------------------------------------------- |
| **可无缝循环**   | 环境音必开（见下一节）                                                |
| **期望时长**     | 规范范围 **0.5–30 秒**。注意是"期望"，不是精确裁切                    |
| **提示词影响力** | **0–1**，默认 **0.3**。给低一点让模型自由发挥，给高一点更贴合你的描述 |

> **一个容易踩的坑**：想表达"很短促"时，**写在提示词里**（"短促、干净不拖尾"）就行 ——
> 那里是自由文本。但 **「期望时长」那个数值框有下限 0.5 秒**，填 `0.1` 会被上游拒。
> 想要 0.1 秒的音效，就留空让它按描述生成、再在时间线上裁。

点运行。**几秒到十几秒**出结果，比出图快得多。

### ③ 它已经在你的工程里了

落盘到 `Cache/Sfx`，可以直接接下游、上轨道。

**这里要提醒一句**：音效端点的模型是**唯一取值**（`eleven_text_to_sound_v2`），所以节点上那个下拉**不是在选模型，是在选"用哪个提供商实例"**。如果你有多个 ElevenLabs 账号 / 多个 Key，它才是入口。

> 顺带说个我们刚修的坑：以前这个节点会报「当前模型提供商不支持音效生成」——**哪怕你配好了 ElevenLabs**。原因是它按"你在音频页签勾过模型"来挑提供商，而你勾的可能是 OpenAI / MiniMax / 方舟（它们有语音合成但**没有音效端点**）。如果你踩到过，升到 7.1.1 就好了。

## 三、内置 22 个游戏音效预设：从转场到环境音

不想从零写描述的话，时间线上有个**内置音效库**，按三类分好：

### 转场（8 个）

呼啸转场 · 快速轻转场 · 重击转场 · 上升紧张转场 · 下坠收尾转场 · 故障电子转场 · 挥动甩镜转场 · 低频轰隆转场

### UI 音效（7 个）

清脆点击 · 轻柔点按 · 提示音 · 通知提示 · 弹出音效 · 确认成功 · 操作错误

### 环境音（7 个）

雨天环境 · 森林鸟鸣 · 人群嘈杂 · 风声 · 海浪 · 咖啡馆环境 · 雷雨

**每个预设都带中文和英文两套提示词**，跟着你的界面语言走。点一下就生成，也能把预设当模板改词再生成。

预设的提示词写法值得抄 —— 比如「轻柔点按」那条：

> 轻柔温和的触控点按音效，柔和不发闷

**它在描述声音的质感，而不是在说"我要一个按钮音效"。** 这就是下一节要讲的。

## 四、最容易被忽略的那个开关：「可无缝循环」

游戏环境音和"播放一次的音效"是两种东西，别搞混：

|                   | 典型素材                       | 关键要求           |
| ----------------- | ------------------------------ | ------------------ |
| **一次性音效**    | 点击、命中、拾取、转场         | 起音干脆、尾巴干净 |
| **环境音 / 循环** | 雨、风、海浪、机器嗡鸣、BGM 层 | **首尾必须衔接**   |

对第二类，**「可无缝循环」是必须开的**。开了之后：

- 素材首尾天然衔接，引擎里直接 loop，**没有接缝咔嗒声**
- 不需要事后切零交叉点、不需要手工交叉淡化

**顺带一个反直觉的点**：环境音**不要追求"短"**。写 10 秒左右，让模型有空间铺出层次（远近、起伏）；太短反而容易听出规律性重复。

## 五、写好提示词：描述声音本身，不要描述意图

这是我见过最多人写错的地方。

### ❌ 不要写："我要一个 UI 按钮音效"

模型不知道你的游戏是什么风格，这句话等于没说。

### ✅ 要写：**描述这个声音听起来是什么样**

```
清脆短促的按钮点击，颗粒感清晰，干净不拖尾
```

拆开看，一条好提示词通常包含四层：

| 层              | 例子                               |
| --------------- | ---------------------------------- |
| **音色 / 质感** | 清脆、低沉、金属感、气泡感、颗粒感 |
| **时间形态**    | 短促、绵长、渐强、下坠、一次性     |
| **空间 / 混响** | 干净无混响、大厅混响、远处、贴耳   |
| **排除项**      | 不刺耳、无杂音、不拖尾             |

**最后一条"排除项"特别有用。** 模型经常给你加一些你没要的东西（多余的尾音、底噪、混响），直接写"干净无混响"比事后处理省事得多。

### 一个可以直接抄的模板

```
<音色质感>的<什么声音>，<时间形态>，<空间感>，<排除什么>
```

举例：

- `清脆短促的按钮点击，颗粒感清晰，干净不拖尾`
- `有力的低频重击，伴随短促轰鸣，冲击感强，无杂音`
- `持续的雨声，均匀细雨落在地面的沙沙声，舒缓宁静`

### 关于「提示词影响力」

- **调低（0.1–0.3，默认 0.3）**：模型自由发挥更多。适合"我也说不清，你先给我几个"
- **调高（0.6–1）**：更严格贴合你的描述。适合你已经想清楚了

## 六、怎么进到游戏里

### 路径一：当素材用

生成 → 落盘 `Cache/Sfx` → 在成片时间线里上轨、对画面 → 导出成片。

适合**做视频 / 预告片 / 玩法演示**：音效和画面对齐这件事，在时间线上是最直观的。

### 路径二：作为资产进引擎

生成的东西可以登记进**资产库**，带 GUID 引用和 `.aipackage` 导出 —— 和其他素材一样管理。

游戏工程那边引用 `Cache/Sfx` 下的文件即可（Unity / Unreal / Godot 都认 wav / mp3）。

### 路径三：让 Agent 批量灌

内置 **MCP 工具服务** —— Claude Code、Codex 这类外部 Agent 能直接操作你的工程。

所以可以这样干：**写个清单，让 Agent 批量生成一整套 UI 音效**（点击 / 悬停 / 确认 / 取消 / 错误 / 升级），一次跑完。人只需要最后听一遍、挑掉不合适的。

## 七、说点不好听的

### 1. 它替代不了专业音效库

**该买库的地方还是要买库。** 具体说：

| 场景                                 | 建议                   |
| ------------------------------------ | ---------------------- |
| UI 音效、转场、氛围层、占位素材      | **生成足够好，而且快** |
| 枪械、真实载具、特定乐器、标志性音色 | **用专业库**           |

生成的优势是**速度和贴合度**（"我要一个符合我这款游戏风格的点击音"），不是"取代录音棚"。

### 2. 按次计费，且**没有实时试听**

每次生成都是一次 API 调用，要花积分。所以别把"影响力"滑块来回拖着试 —— **想清楚再点**。

也不像本地合成器那样能实时调参试听。

### 3. 「期望时长」不是精确裁切

你填 0.5 秒，模型给的是"大约这么长"。**要精确长度就事后裁** —— 时间线上裁一刀的事。

而且那个数值框**有下限 0.5 秒**（上游规范）。要更短的音效，就靠提示词里的"短促"，别去填数值框。

### 4. 端点只有一个模型

音效端点的 `model_id` 是单值枚举（目前 `eleven_text_to_sound_v2`），所以节点上那个下拉**不是模型选择器**，是提供商实例选择器。别指望在音效节点里换模型。

## 八、最后：怎么开始

**准备工作**：

1. 本仓 GitHub Release 下载（Windows / macOS / Linux）
2. 设置 → 模型 → 添加 **ElevenLabs**，填 API Key
3. 有想法，或者直接用内置的 22 个预设

**第一个推荐动作**：打开时间线的**音效库**，点一下「清脆点击」。

不是为了用那个音效 —— 是让你**看一眼它给的提示词长什么样**。看懂那个写法，后面你自己写的每一条都会好用得多。
