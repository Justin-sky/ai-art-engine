# 教程：安装 REA 技能，从 APK 静态拆解到游戏机制还原、提取数值与反写策划案全闭环

> **适用版本**：AI Art Engine `v8.9.3+`  
> **全程耗时**：约 15～25 分钟（首次配齐本地工具后，后续单包分析可全自动跑完）  
> **核心闭环**：`安装 REA 技能` → `开启工程完全访问` → `APK 架构测绘与反编译` → `核心玩法机制还原` → `数值配表与公式提取` → `反写标准策划案（GDD）+ Machinations 沙盘验算`

---

## 0. 合规声明与适用场景

本教程面向**游戏策划、数值策划、技术策划（TD）与客户端研发人员**，仅用于以下**合法合规场景**：

- **自有历史工程考古**：团队早期项目策划案遗失、配表散落或代码经过多轮线上热修后文档失真，需从历史构建 APK 中还原真实线上逻辑与数值基线；
- **研发期 QA 与策划走查**：校验打包后的客户端真实结算公式、冷却上限、掉落权重是否与策划原稿一致；
- **开源 Android 游戏工程学习**：拆解开源独立游戏的有限状态机（FSM）、战斗循环与经济漏斗设计。

> **边界原则**：本教程仅涉及标准静态结构解析、状态机梳理与数值公式提取，**不涉及也不支持**任何绕过商业加密壳/DRM、破解授权校验、挖掘安全漏洞或盗用受版权保护美术音视频资源的做法。请仅对拥有合法授权的目标包执行分析。

## 1. 环境与前置工具准备

AI Art Engine 负责提供 **Agent 大脑 + REA 证据链分析规范 + 策划案/数值沙盘画布节点**；底层反编译命令由本机安装的开源静态分析工具执行。按目标 APK 的引擎类型按需准备（放入系统 `PATH` 即可）：

| 分析层级                  | 推荐本地工具                                          | 作用说明                                                                                     |
| :------------------------ | :---------------------------------------------------- | :------------------------------------------------------------------------------------------- |
| **APK 清单与资源结构**    | `apktool`                                             | 解码 `AndroidManifest.xml`、资源目录 `res/`、`assets/` 结构与可读 XML/JSON 配置              |
| **Java / Kotlin 层**      | `jadx`（含 `jadx` CLI）+ JDK 17+                      | 将 `classes*.dex` 反编译为可读 Java 源码，定位入口 Activity、SDK 桥接与纯原生游戏逻辑        |
| **Native / 引擎脚本层**   | `Ghidra`（`analyzeHeadless`）或 `IDA Pro`（`idat64`） | 分析 `lib/*.so` 原生符号与核心结算函数（如 Cocos C++ / Unity IL2CPP 未剥离符号或元数据关联） |
| **Unity Mono 层（可选）** | `ilspycmd`（.NET CLI）                                | 若 `assets/bin/Data/Managed/Assembly-CSharp.dll` 存在，可直接反编译为干净的 C# 游戏逻辑源码  |
| **配置表解析**            | `Python 3`                                            | 批量提取并转换 `assets/` 下的 JSON / CSV / XML / SQLite 静态数值配表                         |

### 1.1 创建专属分析工程

1. 启动 **AI Art Engine**，新建一个空白工程（例如命名为 `APK_Game_Analysis`）。
2. 在工程根目录下新建 `Inputs/` 文件夹，将待分析的自有/开源包（如 `Inputs/demo-game.apk`）放入其中。
3. 在 **设置 → 模型接入** 中配置支持长上下文与强工具调用的大模型（推荐 DeepSeek 官方模型等），并在 AI 对话面板顶部将模式设为 **`Agent`**（即 Craft 执行模式）。

## 2. 安装 REA（`reverse-engineer-anything`）技能

AI Art Engine 已内置兼容标准 `SKILL.md` 技能生态，并在官方精选索引中收录了 [`morluto/rea`](https://github.com/morluto/rea/tree/main/.agents/skills/reverse-engineer-anything)（**REA: Reverse Engineer Anything**）。

REA 技能最大的价值在于**给 AI 套上严格的「证据链纪律」**：禁止大模型靠函数名瞎猜玩法，强制要求「先测绘引擎栈 → 按假设驱动追踪调用链 → 每条机制与公式必须标注 `[文件路径:行号/函数名]` 证据来源」。

以下两种安装方式**任选其一**：

### 方式 A：在 AI 对话中一句话自动安装（推荐）

直接在右侧 **AI 对话** 输入框发送：

```text
帮我搜索并安装 rea 逆向分析技能
```

或直接粘贴 GitHub 技能目录地址发送：

```text
安装技能 https://github.com/morluto/rea/tree/main/.agents/skills/reverse-engineer-anything
```

- Agent 会自动调用内置 MCP 工具 `skill_search` + `skill_install`，将技能原子安装至 `$DSH_HOME/skills/reverse-engineer-anything/`，当轮对话立即生效。
- 安装完成后，点击输入框下方工具栏的 **「技能」** 按钮即可看到 `reverse-engineer-anything`，后续也可随时输入 `/reverse-engineer-anything` 显式调用。

### 方式 B：通过顶栏「技能市场」窗口可视化安装

1. 点击主界面顶栏右上角的 **「技能市场」** 按钮（位于「设置」左侧）→ 切换到 **「技能」** 页签。
2. 在顶部 GitHub 技能直装输入栏粘贴：
   ```text
   https://github.com/morluto/rea/tree/main/.agents/skills/reverse-engineer-anything
   ```
3. 点击 **「安装」**，卡片显示「已安装」即准备就绪。

## 3. 开启当前工程「完全访问」（关键一步）

默认情况下，AI 对话运行在 **`🛡️ 受限模式`**（`workspace-write` 本地沙箱）下，仅允许写入当前工程目录，且部分外部桌面分析工具（例如 `jadx` 写系统临时缓存、`Ghidra analyzeHeadless` 或 `idat64` 启动子进程）会受到 Windows 低完整性令牌拦截（常见表现为退出码 `255` 或 `Access is denied`）。

在 `v8.9.3+` 中，有两种方式开启当前工程的无阻碍外部工具调用：

1. **提前一键开启（推荐）**：直接点击 AI 对话输入框下方工具栏的 **`🛡️ 受限模式`** 按钮，将其切换为琥珀色的 **`🔓 完全访问`**。
2. **受阻时点「总是允许」联动切换**：如果在受限模式下运行过程中弹出了「沙箱外操作需要你的同意」或「检测到当前操作在受限模式下受阻」卡片，直接点击卡片上的 **「总是允许」** —— 系统会**仅为当前工程**持久化开启完全访问，自动放行后续所有外部命令，同时下方按钮也会实时同步变为 **`🔓 完全访问`**（其他工程依然保持安全的受限模式，互不影响）。

## 4. 四步实战：从 APK 反编译到反写策划案与提取数值

下面按工业级逆向还原的标准四步法推进。你可以分步发送，微调每一阶段重点；也可以直接跳到第 5 节用一条 `/goal` 指令全自动跑完。

### 第一步：APK 解包测绘与引擎栈识别（Triage & Recon）

先不要让 AI 盲目通读几万个类，而是让它先做 **5 分钟快速测绘**，摸清游戏是什么引擎写的、逻辑藏在哪里、配表是什么格式：

```text
/reverse-engineer-anything 请对工程内的 Inputs/demo-game.apk 执行第一阶段静态测绘（先不要全量精读代码）：
1. 在 Cache/re_work/ 下用 apktool / jadx（或解压检查目录结构）完成基础解包；
2. 识别该 APK 的客户端技术栈（原生 Java/Kotlin、Unity Mono、Unity IL2CPP、Cocos2d-x/Creator、Godot 或 WebView H5）；
3. 定位核心玩法代码目录（排除第三方广告/统计/渲染库噪声）以及静态数值配表目录（assets/ 或 res/ 下的 json/csv/xml/db 等）；
4. 输出一份《客户端技术栈与核心模块地图》，列出关键入口类、系统模块划分与配表文件清单。
```

**这一步你会得到**：

- 清晰的引擎判定（例如：_Unity Mono 架构，核心业务全部位于 `Assembly-CSharp.dll` 的 `Game.Battle`、`Game.Economy`、`Game.Config` 命名空间；静态数值表位于 `assets/Configs/*.json`_）；
- 自动排除了 `androidx.*`、`com.google.*` 等 90% 无关第三方 SDK 代码，大幅节省上下文 Token。

---

### 第二步：核心游戏机制与状态机深潜分析

拿到模块地图后，让 Agent 顺着主循环与业务模块还原**真实运行时的玩法规则**：

```text
基于刚才的模块地图，请深入反编译后的核心业务代码，逐一拆解以下游戏机制（每条结论必须注明 [源码文件:类名.方法名] 证据）：
1. 核心玩法循环（Core Loop）：单局从开始、推进、结算到局外养成的完整闭环；
2. 战斗/交互状态机：角色/单位包含哪些状态、状态切换条件、帧/回合推进时序、胜负判定条件；
3. 子系统规则拆解：技能释放与冷却机制、Buff 叠加/刷新/驱散优先级、关卡波次生成逻辑、局外成长/装备/抽卡或商店系统规则；
4. 隐藏机制与边界保护：是否存在保底计数、连败补偿、伤害保底阈值或防刷上限。
```

**为什么效果好**：由于加载了 `reverse-engineer-anything` 技能，AI 不会写出空泛的套话，而是会沿着真实函数调用链把诸如「_暴击判定先于护甲减免还是后于护甲减免_」「_同名 Buff 是独立计时还是刷新层数上限 5 层_」这些只有源码里才写死的硬细节全部揪出来。

---

### 第三步：提取完整数值配表与核心结算公式

玩法逻辑理清后，下一步是把**硬编码常量 + 静态配表 + 结算数学公式**完整提取成策划可直接放进 Excel 或沙盘的结构化文件：

```text
请继续从反编译源码与配置文件中提取本作的全部关键数值与公式，落盘到 Output/numerical/ 目录：
1. 导出核心结算公式清单（Output/numerical/Formulas_Spec.md）：
   - 包括但不限于：最终伤害公式、减伤率曲线、暴击期望、攻速/冷却缩减换算、升级经验需求公式、金币/体力产出与消耗公式；
   - 每个公式必须写出完整数学表达式、各变量对应的代码字段名、上下限截断（Clamp/Min/Max）及源码位置；
2. 用 Python 脚本批量解析配置表与代码常量，导出标准 CSV 配表到 Output/numerical/tables/：
   - 角色/怪物基础属性与等级成长表（unit_stats.csv）
   - 技能倍率、冷却与消耗表（skill_data.csv）
   - 经济产出、商店定价与掉落权重池表（economy_drops.csv）
3. 完成后调用 present_files 把生成的公式文档与 CSV 配表展示出来。
```

运行完成后，对话流中会直接弹出 **📦 交付物卡片**，点击即可在应用内预览公式文档，或一键在系统文件夹打开导出的 CSV 表格。

---

### 第四步：反写工业级《游戏系统策划案（GDD）》并接入画布数值沙盘

最后一步，将分散的技术证据与数值表合成为一份**可直接交给研发立项、重构或调优的标准游戏策划文档**，并利用 AI Art Engine 独有的画布能力做可视化仿真：

#### 4.1 反写完整《游戏系统策划案》

```text
请汇总前三个阶段的代码证据、状态机与数值表，反写一份结构完整的《游戏系统与数值策划案》保存至 Output/Reverse_GDD.md（并同步在当前画布创建一个 asset.gameSystem 策划案节点写入核心内容）：
1. 游戏概述与核心体验闭环（Core Loop 流程图，使用 Mermaid 绘制）；
2. 核心战斗/玩法系统详设（实体属性定义、状态机流转表、帧/回合结算流水线、异常处理边界）；
3. 局外养成与商业化/经济系统详设（货币水龙头 Sources、消耗黑洞 Drains、转换节点与库存上限）；
4. UI 界面流转拓扑（各主界面入口、弹窗层级与核心交互反馈）；
5. 数值体系总览与核心平衡性分析（引用已提取的真实公式与关键成长拐点）。
```

#### 4.2 （进阶杀手锏）一键把提取出的数值装入 `game.economy` 沙盘跑仿真

拿到真实公式与配表后，你可以继续在对话里说：

```text
根据刚刚从 APK 提取出的真实货币产出速率、升级消耗阶梯与商店转化公式，在画布上创建一个 game.economy（Machinations 游戏机制沙盘）节点，还原该游戏前 60 回合/关卡的资源循环，并运行仿真体检，分析玩家在第几关会出现资源卡点。
```

- Agent 会自动调用 MCP 工具搭建完整的 Machinations 资源池（Pool）、源点（Source）、转换器（Converter）与状态门控连线，并执行仿真求解；
- **双击画布上的 `game.economy` 节点**进入全屏沙盘工作台：不仅能看到原游戏真实的经济曲线，还可以直接**拖拽折线图上的 `🎯 终点靶心` 或 `◆ 斜率控制点`** 反推修改后的配平公式，实现「拆解对标 → 沙盘复现 → 数值改良」的完整进化！

## 6. 常见问题与排错速查（FAQ）

1. **运行 `jadx` / `ghidra` / `idat64` 提示退出码 `255` 或 `PermissionDenied`？**
   - 检查 AI 对话输入框底部按钮是否仍处于 `🛡️ 受限模式`。点击切换为 **`🔓 完全访问`**（或在提示卡上点击 **「总是允许」**）后重试即可。

2. **Unity 游戏没有 `Assembly-CSharp.dll`，只有 `libil2cpp.so` 和 `global-metadata.dat` 怎么办？**
   - 说明该包使用了 Unity IL2CPP 编译。若是团队自有构建包，建议优先配合打包机产物中的符号表或使用开源 `Il2CppDumper` 从 `libil2cpp.so` + `global-metadata.dat` 还原类型/方法签名头文件（`dump.cs`）与字符串元数据，再交由 Ghidra 无头脚本定位具体结算函数，Agent 能直接读取 `dump.cs` 快速定位所有类名、字段偏移与枚举定义。

3. **APK 解包后文件太多，AI 检索慢怎么优化？**
   - 让所有临时解包产物统一放在 `Cache/re_work/` 下（避免污染工程资产库 `Assets/`）；并在第一步明确要求 Agent **只对游戏自身包名目录（如 `com/studio/gamename/`）做 Ripgrep/AST 检索**，跳过 `androidx`、`kotlin`、`com/google` 等第三方库目录。
