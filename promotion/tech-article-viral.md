## 正文

### 先讲个真实场景

做一条 15 秒的广告片，你要经过多少步？

文生图出一个产品视觉——图生视频让它动起来——3D 生成一个产品模型做转场——配音、字幕、背景乐——最后在剪辑软件里把时间线拼出来。

每一步对应一个网站、一个软件、一组 prompt、一次登录。素材散落在不同的"最近上传"里，prompt 没有统一管理，改一处产品细节，前面的步骤全部重来。

更难受的是：这些工具大多是**按量付费的订阅制**。你每次点生成，都是一次"点卡扣费"。跑一条完整流程，几十块就没了。而且素材和工程数据都在别人服务器上，你连"备份工程"这个动作都做不了。

这不是我的想象，是我做短剧和广告时每天的真实体验。所以最后我受不了了，决定自己写一个工具。

**AI Art Engine**，一个本地优先的 AI 创作工作站：资产、分镜、节点图、成片时间线，全在一个桌面端里；模型调用走你自己的 API Key；内置 AI 对话和 MCP Server，可以让 Claude Code 直接驱动你的工程。

开源，GPL-3.0，Windows / macOS / Linux 三端都有安装包。

### 一、商业 AI 工具的"三座大山"

我不是来黑商业工具的——即梦、可灵这些产品在单点上确实强。但作为一个要量产内容的创作者/小团队，它们有三个绕不开的问题：

**第一，成本不可控。**
订阅 + 点数 + 单次生成消耗，一条工作流跑下来成本几乎是黑盒。对要做几十条、几百条素材的团队来说，这不是"几十块钱"的问题，是"这个流程跑不跑得起"的问题。

**第二，数据不落地。**
工程在云端，素材在云端，prompt 在云端。导出格式各家不一，备份靠截图，换工具等于重来。做商业素材的团队还会额外多一重担心：**甲方素材传给了第三方服务器**，合规上能不能说清楚？

**第三，失败是黑盒，过程不可自动化。**
生成失败，界面给你一个"生成失败"，没有原因、没有重试策略、没有审计日志。更关键的是，这些工具基本**不可被编程驱动**——你不能让一个 AI Agent 替你去操作它、编排它、批量跑它。

这三座大山，就是我想拆掉的东西。

### 二、开源路线也有另一座山：ComfyUI 的门槛

说到"本地 + 自控"，很多人会想到 ComfyUI。它确实强大，但它解决的是**研究者的需求**，不是**创作者的需求**：

- 节点可以无限自由，但工作流基本靠手搓，没有模板化、没有"一键起一个短剧分镜流水线"；
- 视频 / 3D / 配音能力要靠社区插件拼，维护成本高；
- 生成完的素材没有资产库，没有分镜，没有时间线，**它只解决"生成"这一环，不解决"做片"这件事**。

ComfyUI 的哲学是"给你一块无限大的画布，你自己画"。而我要做的是：**画布给你，但常用的路先铺好**。

### 三、解法：一个本地优先的 AI 创作工作站

AI Art Engine 的核心设计就一句话：**让"做一条片子"这件事，只在一个工程里发生。**

#### 3.1 本地工程 + 资产库

工程 = JSON + 媒体目录，全部落盘本机。图片、视频、声音、3D 模型统一进资产库，用 AssetRef GUID 引用——节点图、分镜、时间线引用的是同一个资产实体，改一处全链路可见。支持 `.aipackage` 导入导出，工程可以整体打包带走或分享。

数据不出本机，这是对"云端黑盒"最直接的回应。

#### 3.2 节点图驱动生成：文本 / 图片 / 视频 / 声音 / 3D

所有生成能力都是节点：文本节点、图片节点、视频节点、声音节点、3D 模型节点。把它们连起来，就是一条生产流水线。

节点图不是"玩具式连线"，它有完整的工程化设计：

- **端口强类型**：单数不能进复数，选取节点只收列表口，连错线在编辑器里就报错，而不是生成到一半才炸；
- **任务队列复用共同上游**：一个上游节点的结果同时喂给多个下游，只生成一次，不重复花钱；
- **任务容错模式**：某个节点失败，链路降级继续，而不是整条流水线报废——这在批量出素材时能救命；
- **媒体质检自动返工**：用专用质检模型做五维评分，FAIL 时把失败原因注入 prompt 自动重试。失败不再是一个黑盒 error，而是一条"哪里不行 + 自动修正"的闭环。

#### 3.3 一键工作流：从模板到可复用宿主资产

预设模板：短剧分镜、游戏 UI、游戏买量、产品广告、电商带货、游戏 3D 资产、漫画出版、知识口播、3D 白模预演……一键生成一个"宿主资产"——外层暴露边界 I/O 口，内部图可以 Dive 进去细看、修改。AI 也可以直接规划拓扑，把一句话需求变成一张可执行的节点图。

#### 3.4 导演台 + 成片时间线

3D 站位截图、动作录制、AI 白模搭场景；全景图自动设为背景；20+ 基础几何体、材质贴图。生成完的素材拖上时间线：画中画、转场、联播预览、导出成片。

到这里，"做片"闭环就齐了：**分镜 → 生成 → 编排 → 成片**，全在一个应用里。

#### 3.5 压轴：AI 对话 + MCP，让 Agent 能"干活"

这是我最想聊的部分。

应用内有一个 AI 助手（DeepSeek Harness 运行时），你可以在对话里 `@` 引用工程资产，让它直接调工具干活：生成图片 / 视频 / 3D / 语音、编辑节点图、运行工作流、查状态。

但更关键的是：**AI Art Engine 内置了一个 MCP Server**。Claude Code、Codex 这些外部 Agent 可以通过 stdio 桥或 HTTP 直连，直接操作你的工程。工具定义只写一份，内部助手和外部 Agent 共用同一套。

这意味着什么？意味着你的创作工具不再是一个"等人类操作"的软件，而是**一个可以被 AI 生态驱动的平台**。你说"把这 30 张图按产品线分好组、每组装一组广告变体矩阵"，Agent 会自己去规划节点图、跑生成、把结果归位。

### 四、技术方向：这些设计为什么"先进"

抛开功能，从技术层面看，这个项目踩准了几个方向：

**1. MCP 是"Agent 驱动一切"的基础设施。**
自造协议永远接不上生态。MCP 是 Agent 生态的事实标准，选择它意味着：Claude Code 生态里的每一分能力都可以无缝接入你的工具。对桌面软件来说，"能被 Agent 驱动"正在从加分项变成必备项。

**2. 生成管线的工程化，而不是"一键出图"。**
把生成从"单次调用"升级为"可编排、可容错、可质检、可复用的流水线"，这是创作工具从玩具走向生产工具的分水岭。端口强类型、共同上游复用、FAIL 自动返工，每一件都是"把不确定的 AI 调用，变成可预期的生产流程"。

**3. 30+ 提供商的统一抽象 + 错误分类哲学。**
OpenAI、DeepSeek、智谱、Kimi、xAI、Google、可灵、MiniMax、通义、火山方舟、vLLM、Ollama、LM Studio、ComfyUI、Meshy、Tripo、Rodin、Luma、Lux3D……统一到一个适配器抽象下，用户自己填 API Key，随意切换，**不被任何一家厂商锁定**。

这里面有个很值得说的设计：面对 Lux3D 这种"单账号单并发"的上游，很多人第一反应是加全局串行队列。但队列会把非冲突失败也串进去，白白拖慢。我的做法是**错误分类 + 指数退避**：只有识别为并发冲突的错误才自动重试（10s 起步翻倍，5 分钟封顶，12 次），其他错误立即抛出。用错误分类替代全局排队，并发不浪费。

**4. 对象存储适配层。**
参考视频 / 3D 参考图需要公网 URL，于是做了火山 TOS / 阿里云 OSS / 腾讯云 COS 三个适配器，预签名 URL + 上传幂等缓存（同一参考图重试不重复上传，不产生孤儿对象）。云厂商差异被隔离在一个 100 行的接口后面。

**5. 可扩展内核。**
Editor Kernel + Cordis 扩展体系（窗口 / Inspector / 节点 / Skill / 执行器），外部插件清单是声明式的。想给这个工具加能力，不需要改主程序。

### 五、与商业软件对比：它到底解决了什么

| 维度 | 商业订阅制工具 | AI Art Engine |
|---|---|---|
| 计费 | 订阅 + 点数，成本黑盒 | 走你自己的 API Key，成本透明可控 |
| 数据 | 云端，不可导出、不可备份 | 本地工程，`.aipackage` 整体打包 |
| 失败处理 | "生成失败"黑盒 | 五维质检 + 原因注入自动返工 |
| 自动化 | 基本不可编程 | 内置 MCP Server，Claude Code / Codex 可驱动 |
| 厂商锁定 | 单家平台 | 30+ 提供商可切换 |
| 批量生产 | 手动一条条跑 | 节点图复用上游、任务容错、变体矩阵 |

不是"替代"，而是补上商业工具长期忽视的那一面：**把控制权还给创作者**。

### 六、给开发者的几个真实踩坑

如果这段对你有用，说明它不是在画饼：

1. **MCP 工具调用超时必须和 HTTP 长超时对齐。**
   `generate_model3d` / `generate_video` 是"提交后阻塞轮询到生成完成"，动辄几分钟。MCP client 默认 60s 超时，Agent 会误判失败并重复提交。对齐到 120 分钟后，这个问题消失。

2. **上传要幂等。**
   Agent 重试、多入口并发时，同一张参考图会被重复上传到对象存储，产生孤儿对象。会话级缓存（文件路径 + size + mtime，或内容哈希）+ 删除时同步失效，是成本极低收益极高的改进。

3. **别把重试做成"无脑重试"。**
   对错误分类：瞬时网络错误可重试，认证 / 参数错误重试一万次也没用。区分对待，用户体验天差地别。
