## 正文

### 先承认：Astra 的演示确实牛

GPT-6 Astra 那段演示你大概率刷到过：屏幕开着 Blender，用户动动嘴——"把角色绑上骨骼，做一个走路循环，头部跟随重心"——模型直接看到视口画面，自己写 bpy 脚本，自己执行，自己截图检查，不对就改。整个 Blender 像是长在了对话里。

评论区一边倒的"AGI 又近了"，外加一句悄悄的"这订阅价格也近了"。

我看完的第一反应和你们不一样。我不是酸，我是职业性地开始**拆解这段演示到底用了哪些能力**：

1. **看**：模型能"看到" Blender 视口画面（多模态输入）
2. **想**：根据画面状态决定下一步写什么脚本（推理）
3. **做**：把脚本送进 Blender 进程执行（工具调用）
4. **查**：执行完再截图，确认结果再继续（闭环反馈）

四件事里，只有第 1 件是 Astra 的"独门"，因为它的多模态是原生实时流。剩下三件——工具调用、脚本生成、看图自查——**任何一家够格的模型 API 都做得到，包括几毛钱一百万 token 的 DeepSeek**。

于是我做了个实验：把第 1 件事用工程手段补上，看整套闭环还能不能转。结论写在前面：能转，而且转得比你想象的顺。这篇文章就是这个实验的完整记录，全部素材来自一个真实工程 `testaa1` 的生成日志，文末可查。

先看结果。

上面这段"少女剑客走路循环"，从一张三视图到带骨骼绑定的 GLB 再到动画预览，**全程 58 分钟，模型调用成本不到一块钱**。中间的每一步——建模、绑骨、调关键帧、渲染预览——都是 DeepSeek 自己看着屏幕（截图）自己干的，我没有碰过 Blender。

### 一、Astra 的"魔法"，拆开其实就三层

先把话说透：Astra 这类实时多模态 agent 的技术壁垒，不在"模型有多聪明"。

工具调用这件事，早就是 JSON 结构化输出的体力活。2023 年的模型都能稳定调函数，2026 年的 DeepSeek 更是闭眼做。真正稀缺的是另外两样：

**第一样：「看」的通道。**
Astra 原生多模态，视口就是它的眼睛。普通模型 API 只收 base64 图片——那我就**把截图喂给它**。AI Art Engine 的 Blender 工具集里有个 `get_viewport_screenshot`：让 Blender 离屏抓一帧视口画面，base64 随 MCP 响应回传给多模态客户端。注意这个细节：画面**只随响应回给模型，不落盘、不进审计日志**——截图里如果有你的商业素材，不会被留在临时目录里。

**第二样：「手」的通道。**
Astra 背后是 OpenAI 花大价钱铺的工具面。我这边对应的是 MCP（Model Context Protocol）——2026 年的事实标准。AI Art Engine 内置了一整套 MCP 工具服务，其中 Blender 组 9 个工具：

| 工具 | 干什么 |
|---|---|
| `execute_blender_code` | 在 Blender 进程内执行 Python，完整访问 bpy / bmesh / mathutils |
| `get_viewport_screenshot` | 视口截图回给模型（上面说的"眼睛"） |
| `export_scene` | 导出 GLB / GLTF / FBX / OBJ / USD / STL |
| `get_scene_info` / `get_object_info` | 场景概览 / 对象详情 |
| `get_world_state_snapshot` | 几何 / 关系 / 动画摘要、当前帧、FPS、激活相机 |
| `describe_node_type` | 查 Shader 节点的端口与属性 |
| `bpy_api_lookup` | 在**运行中的 Blender 里**查 bpy API，参数默认值来自真实 RNA |
| `get_addon_status` | addon 版本 / 协议版本，判断"连不上"是哪种连不上 |

`bpy_api_lookup` 值得单独说一句：Blender 的 API 每个版本都在变，模型训练语料里的 bpy 知识是有"保质期"的。与其让模型凭记忆写 API 然后报错，不如让它先查再说——这是把"幻觉"问题转成了"检索"问题，成本几乎为零。

**第三样：闭环的纪律。**
看一步、做一步、查一步、再走一步。这个纪律 Astra 是靠原生能力撑的；DeepSeek 这边靠的是 harness（后面讲 dsh）在系统层把模式约束住。这一层恰恰是最多人忽略的——**便宜模型跑 agent，纪律不能靠模型自觉，要靠工程**。

### 二、整条链路长什么样

架构一句话：**AI Art Engine（本地工作站）跑一个 MCP 工具服务，dsh harness 驱动 DeepSeek 做agent，Blender 通过 addon 挂进来。**

【配图位 2：架构图——dsh → AI Art Engine MCP 服务 → Blender addon socket / stdio 桥】

几个关键的工程决策，每一个都值得单独拎出来说：

**1. Blender 是"出站直连"，不是子进程。**
AI Art Engine 主动连 addon 在 `localhost:9876` 的监听端口，不装 uv、不起 Python 子进程、不改 Blender 配置。Blender 该开开、该关关，关了这组工具就明确报"连不上 addon"而不是含糊超时。**别把专业软件纳管成你的子进程**——它是用户的软件，不是你的依赖。

**2. 双 addon 兼容，模型侧无感。**
社区方案 blender-mcp 的 `addon.py` 和官方 Blender Lab 的 "MCP Server" 扩展，两套线协议互不兼容，但在工具层被适配成**同一套工具名、同一套入参、同一套输出结构**。模型不知道后端是哪个，用户在设置里切就行。这叫"对模型侧冻结接口"——接口稳定，行为才能被编排。

**3. stdio 桥：让消费 stdio 协议的东西也能进来。**
DeepSeek 的 agent 环境只吃 streamable-http 协议的 MCP server，而业界一堆好东西只暴露 stdio。AI Art Engine 6.3.0 加了一个 stdio→HTTP 反向桥：起一个本地 HTTP 端点，行缓冲把 stdio 包成 MCP over HTTP。第三方 stdio server 从此可以直接注册进对话。**协议适配层永远值得单独造**，比说服上游改协议容易一百倍。

**4. 「看」这件事，我做了三件套，不止截图。**
- 视口截图（上面说的 Blender 眼睛）
- **YOLO 本地打标**：资产入库自动跑本地视觉模型，不耗一分钱 API。工程里那张鹈鹕骑车图，入库时打出的标签是 `bicycle 0.96 / bird 0.68 / umbrella 0.55`——agent 后续用"这张图里有自行车"这种语义查资产，靠的就是它
- **timeline_preview**：出片前用导出同一条 ffmpeg 滤镜图抽帧回传——预览看到的就是成片，不是近似。AI 自己铺的时间线，AI 自己"看片"自查

**5. 护栏：便宜模型的纪律是系统工程。**
`execute_blender_code` 默认开 safe mode：只许 import bpy / bmesh / mathutils 和纯 Python 标准库，禁 eval / exec / subprocess / 网络，禁装饰器 / lambda / class 这类结构性写法（防止拿元编程逃脱词法检查）。同时整个 Blender 工具组受同一套 Ask / Plan / Craft 模式约束——Ask 模式整组不返回，Plan 模式只放行只读工具，`execute_blender_code` 属 write 直接拒并记审计日志。

说句实话：**词法护栏不是沙箱**，它的作用是把"顺手写个 subprocess"挡在门外、抬高逃脱成本；真正的兜底是模式约束。但这两层加起来，一个便宜模型的破坏半径就被压到了专业工具内部——它可以写错脚本搞砸场景，但碰不到你的文件系统。

### 三、实测：一个真实工程的完整记录

下面所有内容来自 `testaa1` 工程的资产库和生成日志，时间戳原样照抄。

**案例 1：少女剑客——三视图到走路循环，58 分钟**

2026-09-12 14:44，先生成三视图母版。原始 prompt（资产库里存着完整版）：

> 角色设定三视图稿：16 岁少女剑客。画面横向并排三个完整全身视图——左侧正面、中间侧面、右侧背面……黑长直高马尾，红色发带束发；深蓝振袖和服，白色宽腰带，白袜木屐；腰侧佩一把黑鞘短刀……日系赛璐璐动画风格，干净利落线稿，平涂上色配硬边阴影。

09-16 早上 06:17，工程里新建 `少女剑客3D` 文件夹，接下来的一小时里资产库陆续落进：

```
06:17  少女剑客·骨骼绑定+走路循环.glb      previewClip: YukiRigAction
06:17  走路循环·01 接触帧.png
06:18  走路循环·07 过渡帧.png
06:46  少女剑客·三视图转3D.glb            （20MB）
07:15  文件夹最后更新
```

注意那四张关键帧的命名：**接触帧 01 / 过渡帧 07 / 接触帧×镜像 13 / 过渡帧×镜像 19**——这是教科书式的 4-pose walk cycle（contact / passing 各一张 + 镜像）。模型不是瞎摆的，它调用的是动画基础功。最终产物 `walk_preview.gif` + `walk_preview.mp4` 落在 `Output/yuki_walk/`。

中间 3D 生成走的是上游模型的 rig 支持：`generate_model3d` 带 `rig` / `rigType` / `rigAnimation` 参数，tripo / meshy / hyper3d 三家 provider 各按自家 schema 透传，骨骼绑定直接在上游完成，Blender 侧做调整和渲染预览——**贵的重活外包给专业生成服务，便宜模型干编排和精修**，这个分工本身就是省钱的关键。

**案例 2：魔幻战士 Q 版砍杀动画**

`魔幻战士Q版·砍杀动画.glb`（27MB）+ `Output/slash_preview/` 下 34 帧砍杀动画预览帧。同一套链路的第二个验证：战斗动作比走路循环复杂得多（重心转移、挥砍弧线、跟随动作），模型同样是"生成 → 截图自查 → 调整"的循环。

**案例 3：鹈鹕骑车——2D 侧的动画**

不完全走 3D：svg.gen 生成矢量动画 → 烘焙帧序列 → 2x4 拼版 sheet → GIF。产出的 `pelican-bike.gif` 入库时 YOLO 打出 `bicycle 0.96` 的标签，后续对话里 agent 用自然语言就能检索到它。中间迭代了 6 个版本（旧版腿、定稿、糖果题……），每个版本的 subgraph 都在资产库里躺着一一可查。

**案例 4：人像 SVG 还原——13 个版本的死磕**

这是我觉得最能说明"便宜模型 + 好工具面"上限的案例。一张人像照片转矢量插画，对话 agent 在沙箱里**自己写了 25 个 Python 脚本**去啃：

```
posterize.py posterize2.py posterize3.py posterize4.py posterize5.py
trace_draw.py  calib.py  flatten.py  isolate.py  bbox.py  verify.py ...
```

同名脚本递增到 v5——它在用脚本做量化色调分离，一遍不行换参数再来。资产库里 `人像转 SVG 矢量插画` 从 v1 迭代到 v13：比例校准 → 坐标强约束 → 脸型与唇形修正 → 发型修正……每一步都有明确的失败分析和针对性策略。**这不是一次生成的运气，这是工程化的迭代能力**——给模型一个能落盘、能跑脚本、能验证的环境，它的行为模式就从"抽卡"变成了"做工"。

顺带一提，工程里还有一份完整的贪吃蛇系统策划案（`gameSystem` 资产）和 `game/` 目录下可玩的 JS 实现，以及一张 3x3 的洗面奶广告矩阵总览——同一个 agent，同一个工程。

### 四、那些 Astra 不用管、你必须管的脏活

用便宜模型复刻旗舰体验，真正拉开差距的不是上面那些光鲜的架构图，是失败路径的工程。挑三个最疼的说：

**1. 一次网络抖动不能判死整条任务。**
3D / 视频生成是 submit → poll 异步模式。早期版本轮询请求一超时就 `failJob` 判死——但 vendor 远端还在真跑，agent 收到"失败"就重发，同一个模型重复生成好几次，**每一次都在计费**。6.3.0 的修法：轮询错误分两类，鉴权类（Key 失效）立即判死，瞬时类（超时 / DNS / 5xx）退避重试——5s / 15s / 30s 逐级退，连续失败满 20 次（约 8 分钟窗口）才放弃，且下载产物阶段单独加 3 次重试。**Astra 用户永远看不见这个问题，因为 OpenAI 用定价替他们付了摆平的钱。** 你要用便宜模型，这个钱就得你自己用代码出。

**2. 词法护栏要处理"字符串里的坏词"。**
safe mode 检查危险调用时，得先抹掉字符串字面量和注释再匹配——否则 `print("bpy.ops.script")` 这种纯字符串就误伤了。护栏自己也会成为 bug 来源，这是写护栏的人的宿命。

**3. 视口截图的最小化边界。**
`get_viewport_screenshot` 离屏抓帧失败会回退窗口抓屏，Blender 最小化时抓不到画面——这些边界不写进文档，用户遇到的就是"玄学失败"。连不上 addon 时报"连不上 addon"，不报含糊超时。**便宜方案的信任，是靠错误信息的确定性一点点攒出来的。**

### 五、账要算清楚

最后回答标题的问题：为什么"廉价 DeepSeek 能媲美 Astra"？

因为这套架构里，**DeepSeek 承担的只是决策层**——看图、决定下一步、写脚本、解析结果。这一层的能力 DeepSeek 早就溢出了，旗舰模型的溢价买的是原生实时多模态和更长的自主性窗口。而"看"和"手"这两头：

- 「看」= 截图回传 + 本地 YOLO + 抽帧自查，**边际成本约等于零**
- 「手」= MCP 工具面，一次性工程投入，**所有模型共享**

Astra 的演示里最贵的那部分（实时多模态流），恰恰是动画制作场景里**最不需要实时**的——动画是异步的：生成一段，看一眼，改一段。截图回传的延迟在这种工作流里完全无感。

至于价格，具体数字我不贴（各家定价变得快），量级感受很直白：上面那个 58 分钟的少女剑客全链路，模型侧开销是 DeepSeek 的 token 计费加上游 3D 服务费，个位数人民币；同样的活儿走旗舰多模态 agent 的订阅/用量计费，自己乘。

**这不是"便宜货碰瓷旗舰"，这是把旗舰的能力拆开，看清楚哪部分是模型、哪部分是工程，然后只为你真正需要的那部分付费。**
