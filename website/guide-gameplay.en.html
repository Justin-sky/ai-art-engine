Guide · Playable HTML · v6.6+

Playable HTML mini-games

Turn a one-line pitch into a tryable prototype: not one-shot chat HTML, but a dsh multi-turn pure Node (esbuild) project, then cook locally into a single file and open the in-app sandbox. Great for game-feel drafts—not a Unity/Godot replacement.

1. What it is

From v6.6 the playable HTML path is:

Step Node / action Output
Brief Text node (or instruction) One-line pitch
Scaffold + agent game.htmlGen Cache/GamePlayJobs/…/project (package.json / build.mjs / src/*.js)
Build asset.gamePlay cook dist/single.html (npm + node build.mjs)
Play Double-click asset In-app iframe sandbox
You need a configured text model (DeepSeek recommended). Generation uses the embedded dsh agent; cook needs a working npm on PATH.

2. Wire three nodes

2.1 Fastest: AI workflow preset

  1. Open AI workflow in the top bar.
  2. Pick One-line mini-game (or describe “playable HTML mini-game”).
  3. Review the preview, then Create workflow and drop it on the canvas.

Typical inner graph: text brief → playable HTML generate → playable HTML asset.

2.2 Manual

  1. Add a text node with controls, goal, and win/lose.
  2. Add Playable HTML generate; wire text to in (optional ref image to in-image).
  3. Add Playable HTML asset; wire the generate node’s project port to asset in.

3. 2D / 3D / Auto

Select the generate node; Inspector has a Mode dropdown (gamePlayMode):

  • 2D Canvas: scaffold without three; agent writes Canvas 2D.
  • 3D Three.js: scaffold includes three and a 3D sample entry; brief forces Three. Pick this when you want reliable 3D.
  • Auto: prompt may choose; scaffold still starts 2D—easy to get “3D copy, 2D project.”
Instruction templates whose names contain “2D / 3D” set the mode automatically.

4. Generate → cook → play

  1. Run generate: logs show dsh editing src/. Don’t race npm install / build yourself—the host does that on cook.
  2. Run the asset node: look for npm install, node build.mjs, and a single-file size.
  3. Double-click the playable HTML node to open the sandbox (WASD / mouse / often R to reset).

Example brief (3D):

Low-poly space-station corridor: pick up energy orbs, WASD move, mouse look, red enemies drain HP, collect 10 to win, R resets; Three.js, crisp look.

5. Resume & folders

  • Generate stores the project relative path in gamePlayProjectDir. Re-running the same node resumes that folder (no fresh scaffold).
  • After cook with a disk path, the full HTML is not stuffed into the card preview (avoids drag lag); the sandbox reads dist/single.html.
  • On disk: Cache/GamePlayJobs/<jobId>/project/ under the project root.

6. FAQ

I chose Auto but it feels 2D?

Auto only tweaks the prompt; scaffold defaults to 2D. Pick 3D Three.js or a 3D-named instruction template.

Cook fails on npm / build?

Ensure Node.js / npm are on PATH; read the node run log. You can npm run build manually in Cache/GamePlayJobs/…/project to compare.

Black sandbox or shader errors?

Custom WebGL (e.g. dFdx) is sensitive to WebGL1/2 extensions. Prefer Three standard materials, or resume the agent to fix. This is a prototype path—not every shader lands in one shot.

How does this relate to film workflows?

It doesn’t have to. Playable HTML is a lightweight gameplay prototype; short-form / ads still use the graph + timeline / director. See Manual § Graph and the short-form guide.
