Reference & troubleshooting

Multi-project workspace file layout (workspace.json + project.json), .aipackage bundles & aiae:graph PNG recipes, the complete shortcut reference, 102-tool MCP setup, and symptom-based troubleshooting.

13. Workspace file structure & asset packages .aipackage

13.1 Local workspace directory layout

AI Art Engine is 100% local-first. Every Workspace lives in a self-contained folder on disk that can be backed up with Git or cloud sync and switched or edited anytime from the expandable left sidebar of ◈ AI Chat:

  • workspace.json + project.json: workspace metadata, active canvas/session state, global style references, global seed, and registered asset index (legacy folders upgrade seamlessly on open).
  • Assets/: curated library assets (canvases, host workflows, scripts, serialized novels, GDDs, images, videos, voices, 3D models).
  • Cache/: intermediate node-graph and Dive workbench outputs (Cache/Images, Cache/Videos, Cache/Voices, Cache/Music, Cache/Sfx, Cache/Models), kept separate until you save items to the library.
  • MCP bridge descriptor: app-managed %APPDATA%/aiartengine/mcp.json (macOS: ~/Library/Application Support/aiartengine/mcp.json) storing the persistent local port and Bearer token for the 102-tool MCP server (never edit by hand).

13.2 Exporting & importing .aipackage bundles

Identified by com.aiartengine.asset-package, asset packages move media and upstream dependencies across workspaces; when you only want to share a node graph topology, you can also drag-and-drop any exported aiae:graph recipe PNG directly onto a canvas.

  1. Export: select assets or a folder in the asset library → right-click “Export asset package” → tick items and optionally enable “Include dependencies” → click “Export”.
  2. Import: right-click empty space in the asset library and choose “Import asset package” (or drag a .aipackage file straight in) → select entries to import with automatic asset reuse and dependency remapping.

15. Troubleshooting

Find your symptom below — entries are ordered by frequency, and most issues are resolved within the first three. If you're still stuck, reach out in QQ group 647306826, by email at 284139554@qq.com, or on GitHub Issues (attaching the run log speeds up diagnosis).

“Insufficient balance”, or everything fails as soon as it runs

Cloud generation calls the model provider you configured yourself (to explore a live Game UI decomposition + 3D Exploded Layer Split → .psd / Unity / Godot pipeline with zero API keys first, click “⚡ Zero-Key Instant Demo” inside ◈ AI Chat).

What to check, in order:

  1. Sign in to your provider console and confirm remaining balance / quota.
  2. Settings → Models: confirm the API key is valid, unexpired, and unrevoked.
  3. Confirm target models are ticked and enabled, and default text / image / video models are set.
  4. Test the same node with another model to isolate account issues from single-model outages.
Invalid key, 401 / 403, or the model list won't load
  1. Check for stray spaces or line breaks around the key; re-copying usually fixes it.
  2. Confirm your key has access to the target model on the provider console.
  3. If using NewAPI or another relay gateway, verify the base URL includes /v1 where required.
  4. On restricted corporate networks, configure a proxy in Settings and check for HTTPS inspection.
Links won't connect: “port type mismatch”

Ports strictly distinguish singular, plural, and domain types: image won't connect to images, and spatialWorld won't connect straight to model without passing through spatialWorld.export.

Common fixes:

  1. For list inputs (such as “Select image / video / audio / text”), wire from the upstream square port (out-all, or out-shots / out-actions on the 3D Director Stage) instead of the round out port.
  2. Typed ports (storyboard, filmCast, spatialWorld) connect only to matching typed consumers (film.shot, spatialWorld.export), never plain text.

See §8 Node graph.

A node finished but produced nothing, or tasks stay queued
  1. Open the node's run log to inspect the exact provider or parameter error.
  2. Confirm all upstream nodes completed.
  3. Check whether the background task queue is occupied by another long job.
  4. On gallery nodes, verify which history item is selected as the active round out in the Inspector.
Characters “change faces”, outfits drift, or voices mismatch across shots

Lock consistency through the 5-stage Film Workbench (film.workbench) rather than repeating text descriptions:

  1. Use Stage 3 #variant anchors, STYLE01 & TTS voice binding: generate turnaround sheets, outfit/damage variants (e.g. CHAR01#battle, CHAR01#casual), location/prop plates, global style card STYLE01, and persistent cross-episode TTS voice bindings.
  2. Let Stage 4 inject locked @1–@4 anchors + Vision QC: Batch Shoot automatically binds each shot's appearing entities as @1–@4 references and auto-reshoots defective frames via Vision QC.
  3. Run Stage 2's 11-point continuity audit to fix axis flips, wardrobe mismatches, and dialogue gaps (≥67% coverage gate) before rendering.

See §9.2 5-Stage Film Workbench and the Short-Drama Guide.

Images look soft, or Game UI button labels look garbled
  1. For general artwork, append the 10-in-1 Image Processing (image.process) node set to upscale (2K / 4K).
  2. For Game UI screens, don't rely on raw full-screen diffusion text: assemble crisp screens from real sprite atlases via ui.componentLib + ui.atlasCompose, or run image.layerSplit with offline/cloud OCR + 9-slice clean plate inpainting to export a .psd with native Photoshop TySh editable text layers.
Video doesn't move, camera blocking drifts, or a reference video is ignored
  1. Write explicit subject action and camera movement in the motion prompt; for locked choreography and camera moves, record an offscreen .webm trajectory white-box clip in the 3D Director Stage (director.stage) and pass it as @2.
  2. When cloud video models require a reachable URL for local reference videos, enable one object storage provider in Settings (TOS / OSS / COS / Amazon S3–compatible; private buckets issue ~24h signed URLs automatically). See the S3 setup example.
Object storage won't configure, or video URLs won't open
  1. Only one object storage provider can be enabled at a time — disable the previous one before enabling another.
  2. Private buckets work out of the box via ~24-hour signed URLs when the public base URL is left blank.
  3. Verify AccessKey read/write permissions and Region (e.g. ru-central1 for Yandex Object Storage — see §4.4).
ComfyUI won't connect, or reports a workflow format error
  1. Confirm comfy-api-proxy is running locally on the configured port and ComfyUI itself is reachable.
  2. Export workflows in API Format (“Save (API Format)” with Dev Mode enabled in ComfyUI), not UI format (nodes / links arrays). See the ComfyUI guide.
Fails to start, blank screen, or update fails
  1. Confirm the installer matches your CPU architecture (Intel vs. Apple Silicon on macOS).
  2. Allow the app under OS security settings if Gatekeeper / SmartScreen prompts on first launch.
  3. Re-check under Settings → General → About & updates or install the latest GitHub Release over your existing copy; back up your workspace folder (workspace.json + project.json and Assets/) before resetting config.
How do I drive the app from Claude Code / Cursor / Codex via MCP? (102 MCP tools)

AI Art Engine embeds a dual-endpoint MCP server (93 tools on /mcp + 9 Blender bridge tools on /mcp/blender = 102 tools) so external agents can install Skill Marketplace bundles (skill_install + workflow_use_installed), edit node graphs (graph_edit), run tasks (task_run), drive Machinations v2 (machinations_studio), run offline OCR (vision_local_ocr), and extract web articles/videos (web_extract_article, web_fetch_video). With the app running, pick either setup:

  1. stdio bridge (recommended, Node.js 18+): run claude mcp add aiartengine -- node <install-dir>/resources/mcp-bridge.mjs.
  2. HTTP direct (zero Node.js dependency): copy the command from Settings → MCP, or run claude mcp add --transport http aiartengine <endpoint> --header "Authorization: Bearer <token>".

Restart your agent session after registering. Never hand-edit the app-managed mcp.json. Full walkthrough: MCP setup guide.

AI Chat errors / web search returns nothing / scheduled automation didn't fire
  1. Model unavailable (HTTP_404 etc.): verify the selected text model exists on your provider account and its API key is enabled under Settings → Models.
  2. Web search & extraction: both built-in ◈ AI Chat (native web_search / web_fetch) and MCP (web_extract_article, web_fetch_video) use the provider configured in Settings → Web Search (§4.6) — verify your search key or network proxy there if lookups fail.
  3. 24-hour Scheduled Automations (00:00–23:59): schedules execute locally while the desktop app process is running (minimized to tray is fine); ensure the app wasn't quit and the schedule toggle is enabled (see §5.8 Scheduled Automations).
  4. Missing chat history after switching projects: expand the left sidebar inside ◈ AI Chat and switch back to the target workspace.
When diagnosing, run the same node with a different model — it's the fastest way to tell “an app problem” from “a model / account problem”.

16. About & updates

Path: Settings → General → About & updates.

  • Current version: shown as v{version} (e.g. v8.9.1; pre-releases are flagged as prerelease).
  • Check for updates: queries GitHub Releases (skipped in local dev mode).
  • States include: checking, new version found and downloading, already up to date, download progress, failure.
  • Click Restart and install once downloaded — all local workspaces (workspace.json + project.json) and provider keys stay intact.
  • Changelog: full release history lives in CHANGELOG.
