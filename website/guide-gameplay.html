Guide · Playable HTML · v6.6+

可玩 HTML 小游戏

用一句话玩法生成可试玩原型：不是聊天框吐一整页 HTML，而是 dsh 多轮写纯 Node（esbuild）工程，再在本机 cook成单文件，双击进沙盒开玩。适合玩法草案，不替代 Unity / Godot。

1. 它是什么

从 v6.6 起，可玩 HTML 链路是：

步骤 节点 / 动作 产出
写需求 文本节点（或指令） 一句话玩法
生成工程 game.htmlGen（可玩 HTML 生成） Cache/GamePlayJobs/…/project（package.json / build.mjs / src/*.js）
构建 asset.gamePlay（可玩 HTML）cook dist/single.html（npm + node build.mjs）
试玩 双击资产节点 应用内 iframe 沙盒
需要已配置文本模型（推荐 DeepSeek；也可用其它兼容提供商）。生成走内嵌 dsh Agent，cook 需要本机可执行 npm。

2. 三条节点怎么连

2.1 最快：一键工作流

  1. 顶栏打开一键工作流。
  2. 选预设一句话小游戏（或描述「可玩 HTML 小游戏」让 AI 规划）。
  3. 预览拓扑后创建工作流，拖入画布。

内图通常是：文本简报 → 可玩 HTML 生成 → 可玩 HTML 资产。

2.2 手动搭建

  1. 新建文本节点，写一句话玩法（操作、目标、胜负）。
  2. 添加可玩 HTML 生成，把文本接到 in（可选参考图接 in-image）。
  3. 添加可玩 HTML资产节点，把生成节点的工程口接到资产 in。

3. 2D / 3D / 自动

选中「可玩 HTML 生成」节点，右侧 Inspector 里有模式下拉（参数 gamePlayMode）：

  • 2D Canvas：脚手架无 three，Agent 写 Canvas 2D。
  • 3D Three.js：脚手架带 three 依赖与 3D 样例入口；brief 强制 Three。要稳定出 3D，请显式选此项。
  • 自动：提示词允许自选；脚手架仍按 2D 起。容易「文案像 3D、工程却是 2D」。
选指令模板时，名称含「2D / 3D」的模板会自动写入模式（例如「3D 收集」「3D 竞技场」）。

4. 生成 → cook → 试玩

  1. 运行「可玩 HTML 生成」：日志里会出现 dsh 多轮改 src/。不要自己在工程目录里抢跑 npm install / build（宿主 cook 时会做）。
  2. 运行「可玩 HTML」资产节点：日志出现 npm install、node build.mjs、单文件体积即 cook 成功。
  3. 双击可玩 HTML 节点：打开沙盒试玩（WASD / 鼠标等以游戏为准；常见 R 重置）。

示例一句话（3D）：

低多边形太空站走廊里捡能量块，WASD 移动，鼠标转向，碰到红怪扣血，捡满 10 个过关，R 重置；用 Three.js，画面干脆。

5. 续跑与工程目录

  • 生成节点会把工程相对路径记在 gamePlayProjectDir（Inspector 可看到）。再次运行同一节点会续跑同目录，不重建脚手架。
  • cook 有落盘路径时，不再把整页 HTML 塞进节点预览（避免拖拽卡顿）；沙盒从 dist/single.html 读取。
  • 磁盘位置：工程根下 Cache/GamePlayJobs/<jobId>/project/。

6. 常见问题

为什么选了自动却像 2D？

「自动」只影响提示词；脚手架默认 2D。要 3D 请在 Inspector 选 3D Three.js，或使用带 3D 字样的指令模板。

cook 报 npm / build 失败？

确认本机 PATH 有 Node.js / npm；看节点执行日志中的具体报错。可进 Cache/GamePlayJobs/…/project 手动 npm run build 对照。

沙盒黑屏或着色器报错？

复杂自定义 WebGL（如 dFdx）对 WebGL1/2 扩展较敏感；可改玩法为 Three 标准材质，或续跑让 Agent 修。这是原型链路，不保证任意着色器一次通过。

和影视成片有什么关系？

没有强绑定。可玩 HTML 是轻量玩法原型；短剧 / 广告成片仍走节点图 + 时间线 / 导演台。见手册 §8 节点图与 短视频教程。
