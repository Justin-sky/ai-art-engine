Guide · v8.9.1 · Playable HTML5 & Game Production

可玩 HTML5 小游戏与游戏量产套件

在 AI 对话面板（或外部 MCP 客户端）里说一句话玩法，Agent 就写出一整个纯 Node（esbuild）2D / 3D 工程：几何、贴图、材质、音效、关卡全部由代码程序化生成，宿主在本机打包单文件并自动执行无头 Chromium 冒烟门禁（零报错 + 模拟输入 + Canvas 帧差分校验），点卡片上的「试玩」即在浏览器开玩；还可无缝衔接一句话游戏套装、16 类分层 PSD 游戏 UI 与 game.economy Machinations v2 数值模拟工作台。

1. 它是什么

这条链路由内置对话面板或 MCP 游戏生产工具组驱动（画布内不再保留旧版「可玩 HTML 生成」加工节点）：

步骤 谁做 产出
写需求 你在对话里说一句话玩法 一句话玩法（Agent 自己整理成工程需求）
落工程 工具 gameplay_prepare_project Cache/GamePlayJobs/…/project（package.json / build.mjs / src/core / src/assets 骨架）
写代码 Agent 用它自己的文件工具改 src/** 程序化资产 + 玩法（几何 / Canvas 贴图 / 音效 / 关卡）
构建与门禁 工具 gameplay_build（宿主执行 esbuild + 无头 Chromium 冒烟测试） 自包含 dist/single.html 单文件 + smoke 实机校验报告
试玩 对话产物卡上的「试玩」 系统默认程序（浏览器）里开玩；同时自动登记一个 gamePlay 资产
需要已配置文本模型（推荐 DeepSeek、Claude 或兼容推理模型）与本机 Node / npm（cook 用）。生成走对话面板里的 Agent（或外部 MCP），npm 与冒烟校验均由宿主安全执行，不要在工程目录里手动抢跑。

2. 在 AI 对话里怎么做

打开右侧 AI 对话面板（模式选 Agent），直接说玩法即可，例如：

低多边形太空站走廊里捡能量块，WASD 移动，鼠标转向，捡满 10 个过关；用 Three.js

Agent 会依次调用三个工具：

  1. gameplay_prepare_project：落下脚手架（可指定 mode: 2d | 3d | auto 与游戏名）。
  2. 它自己写 src/assets/**（程序化资产）与 src/game/**（玩法）。
  3. gameplay_build：宿主执行 npm install + node build.mjs 并启动无头 Chromium 冒烟门禁，返回 jobId；用 gameplay_job_status 轮询到 done。

构建与冒烟通过后，对话流里出现一张游戏卡，卡上只有一个「试玩」按钮，点击直接用系统默认程序打开游戏。

2D 还是 3D 由你一句话里的意思决定；想稳定出 3D 就明确说「用 Three.js」。资产层约定（目录结构、defineAsset 契约、贴图与音效配方）写在内置技能 gameplay-proc-assets 里，Agent 会自己加载。

3. 资产全部由代码生成

这是这条路线的核心：不下载素材、不调用付费生成接口，一切都在生成的工程里合成——所以零额度、秒级出资产、同一种子可复现、风格天然自洽。

  • src/core/rng.js：种子随机（改一个字符即换一整套资产）。
  • src/core/palette.js：一套自洽配色，贴图 / 材质 / 灯光共用。
  • src/core/registry.js：defineAsset({ id, kind, build }) 注册表。
  • src/assets/geometry/：BufferGeometry 造形体（挤出 / 旋转 / 合并 / 实例化）。
  • src/assets/texture/：Canvas 2D 画贴图（条纹 / 噪点 / 渐变），返回可当 CanvasTexture 用的画布。
  • src/assets/audio/：WebAudio 合成音效（振荡器 + 滤波 + 包络）。
  • src/assets/level/：关卡布局由种子推导。

4. 生成 → 构建 → 无头 Chromium 冒烟门禁 → 试玩

  1. 生成：对话里说玩法；日志里能看到 Agent 编写 src/**。选 3D 时脚手架自带 three 依赖与标准入口。
  2. 构建与无头 Chromium 冒烟门禁（Headless Chromium Smoke Verification）：gameplay_build 完成单文件打包后，宿主会自动拉起一个隐藏的无头 Chromium 沙盒实例真实运行编译出的 dist/single.html 数秒，执行三重硬核验收：
    • 零控制台与页面异常（Zero Console / Page Errors）：全程监听 console.error、未捕获的运行时 pageerror、WebGL 着色器编译报错与资源加载失败。
    • 模拟真实玩家输入（Simulated Input）：向页面自动派发指针点击（Pointer/Click）与键盘方向键 / WASD / 空格输入事件，自动跨过「点击开始」标题页并驱动角色运动。
    • Canvas 像素帧差分校验（Canvas Frame-Diff Validation）：连续截取多帧 Canvas 画面比对像素分布与帧间差分，严查整屏纯黑/纯白（未渲染）或画面完全静止（主循环卡死）；结果写入 gameplay_job_status 的 smoke 字段，若 smoke.ok === false，Agent 会依据报错堆栈自动修复代码并重新构建，确保交到你手里的卡片「点开就能玩」。
  3. 试玩：点游戏卡上的「试玩」——自包含的单文件用浏览器打开，能全屏、能开 DevTools；若产物不自包含（用了 ES 模块或相对引用），会自动退回应用内试玩窗口并说明原因。
  4. 资产库也能玩：构建成功会自动建一个 gamePlay 资产，在资产库里双击（或右键「试玩」）走应用内沙盒窗口。

5. 迭代与工程目录

  • 接着说「再暗一点 / 加个跳跃音效 / 换个种子」即可：Agent 只改 src/assets/** 与 src/game/**，再 gameplay_build 一次。
  • 同一个工程重复构建复用同一条作业与同一个资产，卡片原地更新——不会把对话和资产库刷成一串重复条目。
  • 磁盘位置：工程根下 Cache/GamePlayJobs/<jobId>/project/，单文件在 dist/single.html。

6. 配套游戏量产工具与 Machinations v2 数值模拟

当玩法原型跑通后，AI Art Engine v8.9.1 还提供一整套面向商业游戏研发的节点与 MCP 游戏工业化工具组，将「原型验证 → 数值平衡 → 美术资产与 UI 拆层 → 引擎导出」串成完整管线：

  • game_one_sentence_create（一句话游戏全案生成）：输入一句核心创意，自动协同产出游戏策划结构、配置数据表、核心美术资产与可交互原型骨架。
  • game_ui_suite_create（16 类游戏 UI 套件与原生 TySh 分层 PSD）：一键生成主界面 HUD、背包、商城、抽卡结算、技能栏等 16 类成套游戏 UI，自动拆分前景图标、九宫格底板并写入原生 Photoshop TySh 可编辑文字图层（.psd），可直接导入 Unity UGUI 或 Godot 工程。
  • game_playable_preview_compile（可玩预览整合编译）：将画布或工具生成的关卡瓦片地图（game_level_map_generate）、JSON/CSV 数值配置表（game_data_table_generate）、着色器粒子（game_shader_particle_generate）与 UI 资源编译为即点即试的 HTML5 买量试玩包（Playable Ads）或交互预览页，并可通过 game_bundle_export 导出 Unity / Godot / Unreal 引擎目录包。
  • game.economy 节点 & machinations_studio（Machinations v2 经济数值模拟工作台）：内置完整 59 类建筑积木块（资源池 Pools、源点 Sources、转换器 Converters、门控 Gates、随机触发器、延时管道与公式寄存器，可通过 machinations_building_blocks 查询），支持可视化绘制游戏养成/抽卡/战斗循环图，执行单步确定性推演与千次级蒙特卡洛（Monte Carlo）随机模拟，在写正式业务代码前提前定位通胀崩盘与卡关瓶颈。🎮 点此免安装打开在线试玩沙盘 →

7. 常见问题

构建报 npm / build 失败？

确认本机 PATH 有 Node.js / npm；用 gameplay_job_status 看日志尾部与 error。也可进 Cache/GamePlayJobs/…/project 手动 npm run build 对照。

点「试玩」没开浏览器 / 开出来是编辑器？

「试玩」用的是系统默认程序；若把 .html 关联到了编辑器，就会打开编辑器。这种情况改用资产库里的应用内试玩窗口即可。

游戏在浏览器里白屏，应用内却正常？

说明产物不是自包含的：file:// 下浏览器会拒绝执行 type="module" 脚本，也读不到相对的兄弟文件。让 Agent 保持 index.template.html 的内联经典脚本（别加 type="module"、别引相对文件）即可。

画面黑屏或着色器报错？

先看 gameplay_job_status 的 smoke：构建成功后宿主会在无头 Chromium 里执行冒烟校验（模拟按键/指针输入 + Canvas 帧差分检测），控制台报错 / 未捕获异常 / 加载失败 / 整屏全黑 / 帧画面零变化都会记录在 smoke.errors 或 smoke.warnings 中。把报告交给 Agent 让它再改一轮即可。

如果门禁是通过的、只是画面不理想：复杂自定义 WebGL（如 dFdx）对 WebGL1/2 扩展较敏感，可要求改用 Three 标准材质。

图里原来的「可玩 HTML 生成 / 可玩 HTML」节点呢？

已下线：游戏生成改为对话与 MCP 驱动。旧工程里的生成节点会迁成备注节点（保留玩法需求原文）并提示改用对话；旧的「可玩 HTML」资产节点保留可用（能显示、能双击试玩），但不再出现在右键菜单里。

如何从 Claude Code / Cursor 通过 MCP 调用这套游戏工具？

开启「设置 → MCP 服务」后，外部 Agent 可直接调用 gameplay_prepare_project、gameplay_build、gameplay_job_status 以及 game_one_sentence_create、game_ui_suite_create、game_playable_preview_compile、machinations_studio 等 15 个游戏工业化工具，详见 MCP 接入完整指南。
