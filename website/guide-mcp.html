Guide · MCP · v9.0.0

MCP 接入教程（102 工具全量参考）

把 AI Art Engine 接入 Claude Code、Cursor、Codex、Windsurf 等外部 AI Agent：应用启动后在 127.0.0.1:43110 提供本地 Streamable HTTP MCP 工具服务（93 个 /mcp 主工具 + 9 个 /mcp/blender 实时桥工具，共 102 个），支持一行 npx -y ai-art-engine-mcp 零依赖桥接直连，直接编排类型化 DAG 节点图、检索与安装技能市场工作流、执行视频四轴取证与时间线精剪、生成游戏 UI / Machinations 数值沙盘 / 可玩 HTML5 游戏——完全本地化，无需云账号授权。 应用内置的 ◈ AI 对话面板（v9.0 进程内 Pi Agent 运行时）则在主进程内零 HTTP 回环开销直接调用同一套工具面，并通过 load_toolset 按需懒加载引擎彻底根治 128 工具上限限制。

1. MCP 是什么

MCP（Model Context Protocol）是 AI Agent 调用外部工具的标准协议。接入后，你的编码 Agent 多了一组「AI Art Engine 工业资产工具」，对话即可驱动桌面端： 

Claude Code / Cursor / Codex / Windsurf ──stdio(MCP)──▶ npx ai-art-engine-mcp (或 mcp-bridge.mjs) ──HTTP──▶ AI Art Engine（127.0.0.1:43110）
应用内置 ◈ AI 对话面板（进程内 Pi Agent） ──────────────主进程内存直调（零 HTTP 回环开销 + load_toolset 按需挂载）──────────▶ 102 工具底座
  • 应用每次启动会在 127.0.0.1:43110（占用自动顺延）起一个带 Bearer token 的本地 Streamable HTTP 工具服务，连接信息写入 %APPDATA%/aiartengine/mcp.json（macOS / Linux 路径见下文）。文件跨重启保留，token 稳定不变，客户端配置一次即可；也可在应用「设置 → MCP 接入」中查看或编辑 Token。
  • 零依赖桥接包 npx -y ai-art-engine-mcp（以及安装包内置 resources/mcp-bridge.mjs / 仓库内 scripts/mcp-bridge.mjs）由外部 Agent 客户端按需拉起，自动读取本机 mcp.json 完成 stdio ↔ HTTP 协议转换。
  • 通信仅限本机回环地址；除健康检查外全部需要 token 鉴权，并支持基于请求头的 Craft (Agent) / Plan / Ask 模式权限隔离（X-MCP-Mode / X-AIArt-Mode）。
前置条件：AI Art Engine 桌面应用处于运行状态；使用 stdio 桥（npx -y ai-art-engine-mcp 或 mcp-bridge.mjs）需本机装有 Node.js 18+（HTTP 直连方式无需 Node.js）；驱动画布节点运行生成任务时，对应模态的模型需已在「设置 → 模型」中配置启用。

2. 三步接入 Claude Code（两种方式任选其一）

方式 A：stdio 桥（推荐 · 一行 npx 零配置）

  1. 启动 AI Art Engine 桌面应用。
  2. 注册 MCP server（直接运行零依赖 npm 桥接包，或指向安装包 resources/mcp-bridge.mjs / 仓库 scripts/mcp-bridge.mjs）： 
    # 方式 A1：零路径依赖 npx 直连（推荐）
claude mcp add aiartengine -- npx -y ai-art-engine-mcp

# 方式 A2：使用本地桥脚本（无需联网拉包）
claude mcp add aiartengine -- node C:/path/to/ai-art-engine/scripts/mcp-bridge.mjs
    或手动写入 MCP 配置文件（适用于 Cursor、Codex、Windsurf、Trae 等客户端）： 
    {
  "mcpServers": {
    "aiartengine": {
      "command": "npx",
      "args": ["-y", "ai-art-engine-mcp"]
    }
  }
}
  3. 重启外部 Agent 会话，102 工具即可就绪。

方式 B：HTTP 直连（无需 Node.js）

支持 Streamable HTTP 的客户端可跳过桥脚本，token 取自 mcp.json（持久复用）： 

claude mcp add --transport http aiartengine http://127.0.0.1:43110/mcp --header "Authorization: Bearer <token>"

配置模板（.mcp.json）

.mcp.json 是可选文件，需要你手动创建（没有程序会自动生成）—— 新建一个名为 .mcp.json 的文本文件填入下面的内容，放在你运行 Claude Code 的项目根目录， 提交进 git 后团队克隆即用。

单人使用不需要建这个文件：直接执行 claude mcp add aiartengine -- npx -y ai-art-engine-mcp， Claude Code 会自动写入本机配置（~/.claude.json）。两种方式二选一，无需同时做。

stdio 桥版（团队共享免路径依赖推荐用 npx，也可改为本地 scripts/mcp-bridge.mjs）：

{
  "mcpServers": {
    "aiartengine": {
      "command": "npx",
      "args": ["-y", "ai-art-engine-mcp"]
    }
  }
}

HTTP 直连版（无需 Node.js，token 取自应用侧 mcp.json）：

{
  "mcpServers": {
    "aiartengine": {
      "type": "http",
      "url": "http://127.0.0.1:43110/mcp",
      "headers": {
        "Authorization": "Bearer <应用侧 mcp.json 里的 token>"
      }
    }
  }
}
应用侧的连接信息文件（%APPDATA%/aiartengine/mcp.json，结构 { "port": 43110, "token": "…", "pid": …, "version": "…" }）由应用自动写入与删除， 不要手改；token 跨重启复用，要重置删除该文件后重启应用即可。

4. 场景示例

接入后直接用自然语言下指令，Agent 会自动感知当前焦点窗口并组合工具：

  • 「列出我的最近工程，打开第一个并查看工程记忆」→ project_list + project_open + project_memory_read
  • 「搜索技能市场里的短剧工作流，安装后在当前工程新建一份漫剧画布」→ skill_search + skill_install + workflow_use_installed
  • 「在当前自由画布里新建一个图片生成节点接上 10 合 1 图像精修，跑出 9:16 海报」→ graph_node_types + graph_edit（node_upsert + edge_connect）+ task_run + task_status
  • 「隐藏林小满，把她往左移 2 米并转 45 度，设成坐姿」→ director_stage_edit（支持独立 .dstage 与节点图 stage.3d Dive）
  • 「对参考视频做四轴取证拆解，看看前 5 个镜头的景别与台词切点」→ semantic_analyze_video + semantic_timeline_read
  • 「图标包第 3 枚的剑画糊了，只重画这一枚并重跑图集打包」→ graph_icon_refine（cellKey + hint，自动写回并重跑打包）
  • 「搭建一套二次元抽卡经济循环，跑 200 次蒙特卡洛看看第 30 天金币通胀，再导出 Unity C# 脚本」→ machinations_building_blocks + machinations_studio
  • 「生成一套暗黑奇幻风背包 + 商城 + 战斗 HUD 游戏 UI 工作流」→ game_ui_suite_create + task_run
  • 「做个低多边形太空站捡能量块的 3D 小游戏，WASD 移动」→ gameplay_prepare_project（3d）→ 写 src/assets/** 与 src/game/** → gameplay_build + gameplay_job_status 轮询到 done（自动通过无头浏览器试玩门禁），对话卡点「试玩」即开玩

5. 配置与环境变量

桥默认读取 %APPDATA%/aiartengine/mcp.json（macOS： ~/Library/Application Support/aiartengine/；Linux： ~/.config/aiartengine/）。需要覆盖时：

环境变量 作用
AIAE_MCP_CONFIG 指定 mcp.json 的绝对路径
AIAE_MCP_PORT + AIAE_MCP_TOKEN 直连指定端口与 token（优先于配置文件）

应用会依次尝试端口 43110–43119，被占用自动顺延，实际端口以 mcp.json 为准。

5.1 stdio 桥可视化设置

设置页 → MCP 工具服务 → stdio 桥 Tab 可视化配置桥脚本 （无需手写环境变量）。当前可设：桥命令（默认仍是 node + 仓库内 scripts/mcp-bridge.mjs 或安装包内置 <安装目录>/resources/mcp-bridge.mjs）、桥端口 （桥 HTTP 监听端口，默认同上）、Blender addon 的 BLENDER_HOST / BLENDER_PORT 透传。改完即时落盘，外部 Agent 重连即生效，不需要重启应用。

无网或本地开发场景可用仓库内 scripts/mcp-bridge.mjs（正式安装包内置在 <安装目录>/resources/mcp-bridge.mjs）；联网环境直接使用零依赖 npx -y ai-art-engine-mcp 免填路径。同时，你还可以在技能市场或设置页接入任意第三方外部 stdio / HTTP MCP 服务（见 §5.2 外部 MCP 与按需懒加载引擎）。

5.2 外部 MCP 挂载与按需懒加载引擎（内置 Pi Agent 9.0）

除了把 AI Art Engine 暴露给外部 Claude Code / Cursor 调用外，应用内置的 ◈ AI 对话面板（基于 @earendil-works/pi-agent-core 与 @earendil-works/pi-ai 构建的进程内 Pi Agent 运行时，代码位于 src/main/agent/）不仅在主进程内零 HTTP 回环开销直调本机 102 个工作台工具，还能直接连接并消费你添加的任意第三方 stdio / HTTP MCP 服务。

传统 Agent 一旦同时挂载上百个内置工具与多个外部 MCP Server，就会立刻撞上 OpenAI / DeepSeek 等兼容接口的 tools > 128 硬上限报错，并拖慢首字延迟。v9.0.0 通过按需懒加载工具集引擎（load_toolset）从根源解决了这一难题：

  • 精简常驻启动（~24 工具）：每个新会话启动时仅挂载 12 个 Pi Agent 原生工具（文件读写编辑、跨平台终端、skill、load_toolset 等）+ 12 个 studio_core 核心 MCP 工具。
  • 6 大领域工具集 + 外部 MCP 动态按需挂载：其余工作台与 Blender 工具划分为 6 个领域工具集（project_assets、video_timeline_audio、director_3d_blender、game_production、tutorial_recording、skills_web_vision），第三方外部 MCP 服务按 ext:<serverId> 封装（单服超长时按关键词相关性智能筛选 Top 32 工具）。
  • 零回合意图预热 + LRU 淘汰（MAX_ACTIVE_TOOLS = 96 < 128）：发消息前根据用户提示词意图零回合自动预热匹配领域组，对话中模型也可随时调用 load_toolset 自助加载；活跃工具上限严格锁定在 96 < 128（超出按 LRU 自动卸载低频组），并保持回合内工具列表稳定（supportsMidConvoToolAdditions: false），既彻底消灭 128 工具报错，又完整保留大模型 Prompt Prefix Cache 命中率。
  • 统一模式与审计约束：外部 MCP 工具同样追加记录至 <userData>/logs/mcp-audit.jsonl，不会自动获得应用侧 /mcp 写权限，且严格受下节 Craft / Plan / Ask 双层权限闸门管控（Ask / Plan 下绝不放行越权调用）。

6. 双层模式治理（Craft / Plan / Ask）、实时沙箱与安全护栏

  • 双层模式权限隔离（agent.state.tools + beforeToolCall + src/shared/mcpModeAccess.ts）：内置 Pi Agent 在工具列表裁剪与执行前钩子双层拦截，外部 MCP 服务按单次请求头（X-MCP-Mode / X-AIArt-Mode）分级裁剪 tools/list 并在 tools/call 上硬拦截越权调用：
    • Craft（Agent）模式：开放全部读 / 写 / 生成类工具（外部 Claude Code / Cursor / Codex / Windsurf 客户端不带模式头时默认等同此级别）。
    • Plan 模式：在用户通过交互式 ask_user 确认卡批准分步方案之前，仅暴露只读探查工具（如 app_status、graph_read、graph_node_types、asset_qc、skill_search、vision_local_ocr 等），任何改写工程或消耗模型额度的调用均被双层拒绝；用户点击确认后自动解锁执行。
    • Ask 模式：外部 MCP tools/list 返回空集并拒绝一切工具调用（内置对话仅保留只读探查，严禁任何写盘或命令执行），限定为纯问答咨询。
  • 实时沙箱切换与单次失效关闭审批卡（内置 Pi Agent）：对话底栏支持在回合中途实时切换 🛡️ 受限模式（workspace-write）与 🔓 完全访问（danger-full-access）；受限模式下越界命令或高危操作会弹出单次失效关闭（fail-closed）权限审批卡（支持 允许一次 Allow Once / 项目级 始终允许 Always Allow / 拒绝 Reject，超时或异常一律拒绝绝不放行）；会话数据以无锁原子 JSON 存储于 <userData>/dsh-harness/pi-sessions/<sessionId>.json，支持 6 路多工程并行、跨厂商无锁秒切模型、消息回滚分叉与 .zip 导出。
  • 服务只监听 127.0.0.1，Bearer token 鉴权；文件读写被严格限制在工程根目录内（唯一例外是 asset_import：按显式传入的绝对路径读取本机素材并复制入库）；API 密钥绝不对外暴露。
  • 并发闸门：长耗时或消耗额度的同步工具（如 decide、transcribe_audio、semantic_analyze_video、tutorial_compose、gameplay_build 等）同时最多并发 3 个（AIAE_MCP_GEN_LIMIT 可调），超出立即友好报错，防止 Agent 循环失控消耗额度。
  • 操作审计：每次工具调用追加写 <userData>/logs/mcp-audit.jsonl（参数截断、5MB 滚动），生成与写入全程可回溯。
  • graph_edit / graph_icon_refine 对正在画布编辑器中打开的图会协同保护或拒绝冲突覆盖；画布工作流执行为异步任务，统一用 task_run + task_status（或视频作业 video_job_list / video_job_get）轮询追踪。
  • 外部接入方式两选一：stdio 桥（零依赖 npx -y ai-art-engine-mcp，或安装包内置 <安装目录>/resources/mcp-bridge.mjs / 仓库内 scripts/mcp-bridge.mjs，需 Node.js 18+）或 HTTP 直连（无需 Node.js）。

7. Blender 工具集（进阶）

这一组工具不在 /mcp 主工具集里，而是挂在同一服务的另一个端点 /mcp/blender（「设置 → MCP → Blender 工具集」默认开启；关掉后该端点直接回 403，主工具集不受影响）。

让 AI 直接操作本机 Blender —— 搭场景、写 bpy 建模、截图自查画面、导出 GLB / GLTF / FBX 出库。出站直连 addon，不需要装 uv、不起 Python 子进程、不改 Blender 配置：应用主动连 addon 的 localhost:9876。

前置条件

  • Blender 正在运行，且已启用 MCP addon（设置面板里选择对应 addon 类型，两种线协议互不兼容，选错表现为「连接超时」或「连接已重置」）：
    • 社区方案（默认）：blender-mcp 项目的 addon.py，在 Blender 的 Edit → Preferences → Add-ons 安装启用
    • 官方方案：Blender 扩展平台上的 Blender Lab「MCP Server」 官方扩展，安装后在扩展偏好里启动服务
  • 两种 addon 默认端口都是 9876；改过端口就在设置面板里同步填上
  • 外部 Agent 想拿到这组工具，需要再注册一个 MCP server（<token> 取自应用侧 mcp.json）： 
    claude mcp add --transport http blender http://127.0.0.1:43110/mcp/blender --header "Authorization: Bearer <token>"

    应用内的 ◈ AI 对话面板自动带上（内置 Pi Agent 通过 director_3d_blender 工具集进程内直调或零回合意图预热自动挂载），你在对话里说「用 Blender……」即可。

工具清单

工具名称、入参与输出在两种 addon 下完全一致，模型侧无感：

工具 作用 前置条件
get_scene_info 场景概览：场景名、对象 / 材质数量、前若干对象的名称 · 类型 · 位置 Blender 运行中
get_world_state_snapshot 完整快照：几何 / 关系 / 动画摘要、当前帧与帧范围、FPS、选中对象、激活相机与灯光 Blender 运行中
get_object_info 单个对象详情（网格对象带顶点 / 边 / 面数与世界包围盒） Blender 运行中
get_viewport_screenshot 3D 视口截图，画面随 MCP 响应回给多模态客户端（离屏抓帧，失败回退窗口抓屏） Blender 界面可见
execute_blender_code 在 Blender 进程内执行 Python（完整访问 bpy），print 原样返回，报错带异常类型与 traceback Blender 运行中
export_scene 把场景（或选中对象 / 指定对象）导出为 glb / gltf / fbx / obj / usd / stl，配 asset_import 入资产库 Blender 运行中
describe_node_type 查节点类型（如 ShaderNodeTexImage）的端口与可设属性，写着色器 / 几何节点脚本前先问它 Blender 运行中
bpy_api_lookup 在运行中的 Blender 里查 bpy API（操作符 / 类型 / 属性 / 函数），参数名与默认值来自真实 RNA Blender 运行中
get_addon_status addon 版本 / 协议版本 / 能力清单 / Blender 版本，用来判断「连不上」是没启用、版本不匹配还是 Blender 没开 Blender 运行中

典型闭环

get_scene_info            看清现状
   ↓
execute_blender_code      写 bpy 建模 / 调材质 / 摆相机
   ↓
get_viewport_screenshot   截图自查（多模态客户端直接看到画面）
   ↓
export_scene              出 GLB / GLTF / FBX …
   ↓
asset_import              一键入资产库
对话里这样说就行：「在 Blender 里把这几个 Cube 拼成一个底座，做完截张图给我看，调好后导出 GLB 入库」。模型会自己安排 execute_blender_code 的步骤与参数，截图不对再迭代。

安全护栏

  • execute_blender_code 不再做词法护栏：脚本可使用完整 Python / bpy（含 class / lambda / open 等）。写入兜底是 §6 的模式约束 —— Ask / Plan 下整组只读，写入调用被拒。
  • 截图走一次性临时文件：get_viewport_screenshot 让 Blender 写到系统临时目录的一次性文件，应用读回后立即删除；画面只随 MCP 响应回给多模态客户端，不落工程、不进审计日志。
  • 模式绑定请求，不绑定客户端：Blender 端点与主工具集共用 token，Ask / Plan 通过 X-AIArt-Mode / X-AIArt-Run-Id 下发 —— Ask 整组不返回、Plan 只返回只读工具（get_scene_info  / get_world_state_snapshot / get_object_info / get_viewport_screenshot / describe_node_type / bpy_api_lookup / get_addon_status），execute_blender_code 与 export_scene 属 write 被拒并记审计。
  • addon 是 socket 服务端：Blender 一关，这组工具全部失败（错误明确说「连不上 addon」）；应用不负责启动 Blender，也没有无界面模式 —— get_viewport_screenshot 对窗口可见性有要求（最小化时抓不到画面）。连接状态在设置面板里每 4 秒刷新一次，get_addon_status 可随时查版本。
